# Upstream v0.8.0 Selective Port

## TLDR

Operis takes the security, sales/CRM correctness and performance fixes from Open Mercato 0.8.0,
without its new features. 56 upstream changes are ported commit by commit onto `feat/upgrade-om`,
adapted to Operis's own changes, and recorded in
[`docs/architecture/upstream-ports.md`](../../docs/architecture/upstream-ports.md), which lists
every change taken, every one left out, and why.

## Overview

- Source: upstream `v0.8.0` (`ab23d45ffc`), compared against the fork point `3019dc23`
  (NOTICE.md). Upstream changed 5,209 files in that range; Operis changed 6,222; 948 overlap.
- Selected: security (32 changes), sales and CRM correctness (14), performance (10).
- Included prerequisites: upstream `main` hotfixes #5529 and #5623, merged after the fork point but
  before the `v0.7.0` tag; #5460, which #5578 builds on; the #5200 spec, which #5640 implements.
- Excluded: Enterprise-only and MFA changes (ADR-0002), `packages/create-app`, new modules and
  features, and the remaining bug fixes.
- Deferred: #5454, #5843 and #6025 change integration credentials, which
  `feat/per-tenant-env` is rewriting; they are ported after that branch merges.

## Problem Statement

Operis forked four days before upstream tagged 0.7.0 and does not track upstream (ADR-0001), so
upstream security and correctness fixes do not arrive on their own. Its history shares no commits
with upstream, so a merge is not possible, and a wholesale import would pull in Enterprise-licensed
code and undo Operis's own refactors.

## Proposed Solution

Port selected upstream PRs individually, in upstream order, in a dedicated worktree:

1. Read-only `upstream` remote (`main` only, push disabled).
2. `git cherry-pick --no-commit` each PR's commit (`-m 1` for merge commits).
3. Resolve conflicts in favour of Operis's deviations, listed in the ledger: shared helpers,
   design-system table markup, sealed-module imports, entity decorators, migration runner setup.
4. Drop any path under `packages/enterprise`, `.ai/specs/enterprise` or `packages/create-app`.
5. Validate each group, then the whole branch.

## Architecture

No new modules or architectural changes. Notable behaviour carried over:

- ACL edits for roles and users run through commands (`auth.role-acl.update`,
  `auth.user-acl.update`) and are written to the action log (#5365).
- The query engine and CRUD factory cap list `COUNT` at `OM_LIST_COUNT_CAP` (default 10000) and
  return `totalIsCapped` (#5228). Every server-backed `DataTable` forwards it, including five
  Operis-only pages, enforced by `yarn check:pagination-capped`.
- `mercato db migrate` queues a query-index reindex for entity types a data migration declares
  (#5819), controlled by `OM_MIGRATION_REINDEX`.
- Scheduler queue targets are limited to workers that declare `schedulerSafe` (#5455).
- Deals aggregate responses are cached for 30 seconds when the CRUD cache is enabled, keyed by
  tenant, resolved organization scope and filters (#5796).

## API Contracts

- `PUT /api/auth/users/acl`: omitted fields keep their stored values; an organization-only
  override without features returns 400 (#5623, #5537).
- Customer person, company and deal detail routes and their sub-resources return 404, not 403,
  when the record's organization is outside the caller's scope (#5517).
- Public signup no longer reveals whether an email has an account (#5677).
- Channel test-send validates recipients against the provider's capabilities and returns 422 on an
  invalid one (#5261).
- Sales line create/update: `discountAmount` is a line total; optional
  `discountAmountBasis: 'unit' | 'line'` (default `unit`) (#5640). A supplied `totalNetAmount` is
  reconciled and logged when it diverges (#5707). `exchangeRate` and status entry ids are accepted
  on update (#5573).
- CRUD list responses may carry `totalIsCapped: true`; `total` is then a floor (#5228).
- Deal status vocabulary is `lost`; `loose` is still read (#5578).

## Risks & Impact Review

| Risk | Severity | Mitigation | Residual |
|---|---|---|---|
| A list above 10,000 rows shows a capped total ("10 000+"); API clients reading `total` see a floor | Medium | `totalIsCapped` flag, all pagination sites wired, `OM_LIST_COUNT_CAP=0` restores exact counts | External API consumers must read the flag |
| Deal status rewrite cannot be undone by `deploy.sh --rollback` | Medium | Pre-deploy database backup in `deploy.sh`; readers accept both spellings | An older image may not group `lost` deals as lost |
| Stored sales line discounts are now read as line totals | Medium | Read path corrected, upgrade note describes existing data | Integrations sending per-unit amounts keep per-unit meaning unless they send `discountAmountBasis: 'line'` |
| Partial ACL edits now preserve omitted fields instead of clearing them | Low | Upgrade note; clearing requires every dimension explicitly | Scripts that relied on clearing by omission |
| Deferred credential fixes (#5454, #5843, #6025) stay open | Medium | Tracked in the ledger; port after `feat/per-tenant-env` merges | Masked-secret sentinel can still be saved as a value until then |
| Upstream code relying on unported upstream changes | Medium | Missing prerequisites ported (#5460, #5200, #5529, #5623); type check and related tests run per group | Behaviour only covered by Playwright tests, which CI does not run |
